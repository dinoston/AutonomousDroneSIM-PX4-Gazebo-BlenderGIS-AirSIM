# 데이터셋 CSV 및 분석 기능 기획

## 목적

현재 수집하는 RGB·Depth·Segmentation PNG, LiDAR·Radar NPZ와
`frames.jsonl`은 학습과 재처리를 위한 원본 데이터로 유지한다. CSV는 원본을
대체하지 않고, 도시·지형·센서·임무별 비교와 통계 분석에 바로 사용할 수 있는
정규화된 색인으로 함께 저장한다.

의미 있는 데이터는 단순히 프레임 수가 많은 데이터가 아니다. 다음 질문에
답할 수 있는 데이터여야 한다.

- 도시와 지형이 달라질 때 사람·새·드론 탐지 성능이 어떻게 변하는가?
- 거리, 고도, 가림 정도, 이동 속도와 조명이 센서 인식에 어떤 영향을 주는가?
- LiDAR, Radar, 카메라 단독 탐지와 센서 융합 결과는 얼마나 다른가?
- 장애물 회피·재탐색·정지 복구가 얼마나 자주 발생하고 임무 효율에 어떤
  영향을 주는가?
- 동일 면적을 정찰하는 데 걸린 시간, 이동 거리와 실제 관측 범위는 얼마인가?

## 저장 구조

```text
<session>/
  session.json             원본 세션 설정과 완료 상태
  class_map.json           고정 Semantic 클래스 정의
  frames.jsonl             손실 없는 프레임별 중첩 메타데이터
  sessions.csv             세션·도시·환경 조건 1행
  frames.csv               프레임·기체 상태·센서 품질 1행
  objects.csv              프레임 안의 객체 하나당 1행
  events.csv               임무·회피·충돌·정지 복구 이벤트 1행
  session_summary.csv      세션 종료 후 계산한 요약 통계 1행
  rgb/*.png
  depth/*.png
  segmentation/*.png
  lidar/*.npz
  radar/*.npz
```

배열 형태인 이미지와 점군을 CSV 셀 안에 문자열로 넣지 않는다. CSV에는 실제
파일의 상대 경로와 요약 통계만 저장한다. `session_id`와 `frame_id`를 공통 키로
사용하여 모든 표를 연결한다.

## CSV별 핵심 필드

### `sessions.csv`

- `schema_version`, `dataset_name`, `session_id`
- `city`, `region`, `map_name`, `terrain_type`
- `season`, `weather`, `time_of_day`, `visibility`, `scenario_id`, `random_seed`
- 사용 센서, 샘플링 주기, 클래스 맵 버전
- 시작·종료 시각, 저장·누락 프레임 수, 완료 상태

### `frames.csv`

- `session_id`, `frame_id`, UTC 시각과 각 센서 타임스탬프 차이
- RGB·Depth·Segmentation·LiDAR·Radar 파일 상대 경로
- 드론 NED 위치, 고도, 속도, 자세
- 임무 종류, 현재 경유지 번호, 목표 위치, 목표까지 남은 거리
- LiDAR/Radar 점 개수, 탐지 객체 수, 클래스별 객체 수
- 저장 큐 누락 여부와 센서 누락 여부

### `objects.csv`

- `session_id`, `frame_id`, `track_id`, `class_id`, `class_name`
- `sensor_source`: camera, lidar, radar, fusion, ground_truth
- 감지 센서 조합, 실제 정답 여부와 매칭된 예측 ID
- 2D 바운딩 박스와 3D 바운딩 박스 중심·크기
- 월드 좌표, 드론과의 거리, 상대 속도
- 가림률, 화면 잘림률, Segmentation 픽셀 수
- 탐지 신뢰도 또는 시뮬레이션 정답 표식

### `events.csv`

- 이륙, 착륙, 경유지 도착, 장애물 감지, 경로 재계산
- 충돌, API 타임아웃 호버링, 정지 감지와 자동 복구
- 이벤트 시각·프레임·위치, 관련 객체와 상세 사유

### `session_summary.csv`

- 비행 시간·거리·평균 속도·정찰 면적
- 클래스별 등장 객체 수와 유효 관측 프레임 수
- 거리 구간별 탐지율, 센서별 탐지 수, 센서 융합 탐지 수
- 충돌·재탐색·정지·복구 횟수, 프레임 누락률
- 정답 데이터가 준비되면 Precision, Recall, F1과 거리 오차

## 의미 있는 수집 조건

도시별 결과를 비교하려면 같은 클래스 맵과 기본 비행 경로를 유지하고, 아래
조건을 세션 메타데이터로 반드시 기록한다.

- 도심·주거·산업·산지·해안 등 지형 유형
- 낮·밤, 맑음·비·안개와 가시거리
- 고도·속도·카메라 각도
- 사람·새·드론의 밀도와 이동 상태
- 근거리·중거리·원거리, 부분 가림과 완전 노출 비율
- BlenderGIS 메시·텍스처 품질 수준과 맵 버전

유사한 정지 화면만 반복 저장하지 않도록 시간 간격 샘플과 함께 다음 중요
이벤트의 전후 프레임을 우선 보존한다: 새 객체 등장, 클래스 변경, 거리 구간
변경, 가림 변화, 장애물 감지, 경로 재계산, 충돌과 정지 복구.

## 다음 개발 순서

현재 `frames.csv`, `objects.csv`, `session_summary.csv`와 그래프 PDF 자동 생성은
구현되어 있다. 아래 항목은 다음 확장 단계로 진행한다.

1. 비행 이벤트 기록기를 추가해 `events.csv`에 이륙, 경유지 도착, 재탐색,
   충돌과 정지 복구를 기록한다.
2. 날씨·시간대·강수·바람 UI 및 세션/PDF 기록은 구현되었다. 다음으로
   시나리오 ID와 랜덤 시드를 추가해 같은 경로·환경 조건을 재현한다.
3. 사람·새·드론에 지속적인 `track_id`를 부여하고 카메라·LiDAR·Radar 감지를
   같은 객체 행으로 융합한다.
4. 세션 종료 시 `session_summary.csv`를 자동 생성하고 누락률·클래스 불균형·
   센서 시간차를 검사하는 품질 보고서를 만든다.
5. 도시/지형/거리/조명별 탐지율과 임무 효율을 비교하는 분석 스크립트와
   대시보드를 추가한다.
6. RGB 영상에 바운딩 박스·클래스·거리·경로를 겹친 MP4를 별도로 생성한다.
   영상은 시연과 육안 검증용이며, CSV·JSONL·원본 센서 파일을 분석 원본으로
   사용한다.
